<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> relay | Unauthenticated query string from the OAuth provider's redirect, attacker-controllable |
| desktop -> web-search | License key bearer from the desktop app; body text is user content |
| stt-api -> Tavily | Our paid API key leaves the server; Tavily response is untrusted data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | oauthRelayRoute open redirect | high | mitigate | Host fixed to literal 127.0.0.1, port parsed from an anchored regex and range-checked, URL built with the URL API; tests cover a hostile Host header and malformed states |
| T-06-02 | Information disclosure | relay code/state in logs or Referer | medium | mitigate | Existing request log strips the query; no new logging; Referrer-Policy no-referrer and Cache-Control no-store on relay responses |
| T-06-03 | Tampering | relay parameter injection | medium | mitigate | Allow-list of four keys, single string values only, repeated keys rejected with 400 |
| T-06-04 | Spoofing | web-search without a license | high | mitigate | Route stays behind the existing onRequest authorizer (not in PUBLIC_ROUTES); test asserts 401 without bearer |
| T-06-05 | Denial of service / cost | Tavily spend by one license | medium | mitigate | Per-principal 30/min fixed window, numResults capped at 10, query capped at 400 chars, 15 s timeout |
| T-06-06 | Information disclosure | Tavily key or user query in logs | medium | mitigate | Log only status and count; key read from config only, never echoed in errors |
| T-06-07 | Tampering | malicious Tavily response content | low | accept | Results are passed as data; the desktop marks tool output as untrusted model context already (webSearchTool) |
</threat_model>
