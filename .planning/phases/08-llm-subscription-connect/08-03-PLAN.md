## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user to consent dialog | The user approves running a vendor installer from the url shown |
| renderer to main IPC | Renderer asks main to install, sign in and run a prompt |
| renderer display of CLI-provided text | Device URLs, codes and error text originate in vendor CLI output |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Information disclosure | Subscriptions UI and hook | critical | mitigate | Main never sends the token; hook and component never store it; sweep test asserts no renderer source references the token env var (Task 4) |
| T-08-04 | Tampering (installer swap) | consent dialog | high | mitigate | Dialog shows `installSpec.url` and command verbatim and echoes the url; main byte-compares (08-02) |
| T-08-05 | Spoofing | device url shown and opened | high | mitigate | Open-in-browser shown only for `isAllowedSignInUrl` hosts; all other text rendered as plain text, never as HTML |
| T-08-08 | Repudiation or surprise | sign out | medium | mitigate | Confirm dialogs for codex and grok state the terminal CLI is signed out too; claude states the token remains valid until revoked |
| T-08-09 | Policy / ToS | Claude seat | medium | accept | D-04: off by default, toggle, one-line notice; risk recorded in CONTEXT, not re-argued |
| T-08-10 | Elevation (forged IPC) | claude gate | high | mitigate | Gate enforced in main (08-02); UI toggle is convenience only |
| T-08-12 | Information disclosure | provider error text in chat | medium | mitigate | Error strings from main are already redacted; the shim surfaces only the classified code and a translated message |
| T-08-SC | Tampering | npm installs | low | accept | No packages added in this plan |
</threat_model>
