<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> main IPC | Renderer asks main for a service key by URL |
| main -> stt-api (WS, HTTP) | License key leaves the device as a bearer |
| stt-api -> desktop frames/responses | Server-controlled JSON parsed by main and renderer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Information disclosure | titaniumServiceKeyFor callers (meeting, preview, upload, cleanup) | high | mitigate | All four paths get the key only through `titaniumServiceKeyFor`, now backed by the tested `isTitaniumServiceUrl`; foreign hosts get null (Task 1 tests) |
| T-05-09 | Information disclosure | WS URL and debug logs | high | mitigate | Key only in the `Authorization` header; URL builder never adds a query; logs carry URLs and outcomes only (Task 1, Task 6 log review) |
| T-05-10 | Spoofing / Information disclosure | sttApiStreamUrl | medium | mitigate | `wss` required for non-loopback hosts; `ws://` refused outside loopback (Task 1 test) |
| T-05-11 | Tampering | parseSttApiFrame, scribeWordsToSegments | medium | mitigate | Typed parsing, unknown types ignored, non-string or oversized text rejected, numeric start/end required (Task 1, Task 4 tests) |
| T-05-12 | Denial of service | stream pool cap 2 on the server | low | accept | Busy pool surfaces as a meeting/preview error, never a silent retry; capacity tracked as B2 |
| T-05-13 | Information disclosure | prove-stt-parity.mjs | high | mitigate | License from env only, never printed or written |
| T-05-SC | Tampering | npm installs | low | accept | No new packages; `ws` already used by deepgramStreaming.js |
</threat_model>
