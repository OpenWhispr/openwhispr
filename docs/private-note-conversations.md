# Private notes and conversation backup

A conversation that reads Private note content stays on this device, including its later turns and forks. This applies to automatic note context, note tools, Private folder names, and chats opened from a Private note or container. Moving or sharing the source note later does not make the conversation eligible for backup. Legacy shared Private notes may still sync to their guests; the owner's conversations about them remain device-only.

On the first upgrade with conversation privacy tracking, all existing root conversations on this device become device-only, including empty stubs that may receive old history later. Earlier versions did not record which notes automatic context used, so their provenance cannot be recovered. This migration runs once. A conversation first restored from Cloud Backup also becomes device-only: the cloud format has no Private-content provenance, and its client-supplied dates cannot establish that provenance. This includes chats created on another device. A cloud update to an already known local chat preserves its existing classification. Newly created local root chats and local team-note chats remain eligible for backup until they consume Private content. Container chats already remain local because the cloud conversation format has no container scope.

Existing cloud copies are retained. Remote updates and deletions cannot overwrite device-only local history. An explicit user deletion still deletes a conversation's old backup through the existing delete queue; adopting the privacy marker does not delete remote history automatically.

Device-only describes conversation storage and Cloud Backup. It does not change which model answers the request: note context still reaches the inference provider the user selected. Typed or pasted text and externally captured OS selections carry no note provenance and retain their existing behavior. Selections of an answer in the same conversation, and forks of that answer, inherit the conversation's privacy state.

The local database stores a monotonic `agent_conversations.device_only` flag. Renderer turns bind a conversation ID before execution, capture their account, and ask main to protect the conversation before exposing local content or checkpointing it. Main validates ownership and resolves note kind from current and pinned space IDs. If protection fails or the turn changes account or is cancelled, that local content is not returned to the model. Uploads recheck current privacy before sending, and main also fences stale cloud writes and tombstones. The schema-column migration and historical classification commit atomically, without advancing unrelated database migration versions.

Assistant note writes also carry a main-issued account and credential-generation guard. Note creation, edits, and automatic folder creation validate it immediately before changing the database; cancellation after a folder lookup cannot create a folder or note in a replacement account. Calls outside assistant turns retain their existing optional-guard API.
